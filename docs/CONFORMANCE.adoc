# Conformance suite

`spec/conformance/cases/` holds one directory per case class, modelled on
the W3C XML Schema Test Suite category taxonomy. The canonical 2007 suite
distribution is no longer served from w3.org (checked 2026-10-20); cases
here are original, and a vendored upstream subset can be added later with
a provenance + license README alongside it.

## Case layout

```
spec/conformance/cases/<case-name>/
  schema.xsd        # the schema under test
  valid-*.xml       # instances that MUST validate
  invalid-*.xml     # instances that MUST NOT validate
```

## Running

```bash
bundle exec rake conformance
```

Prints a per-mode report and writes `tmp/conformance_report.md`.

Two modes are measured independently:

- **engine** — `Moxml::XSD` tier-1 validation through `EngineContext`
  (leptris when the adapter ships an engine)
- **pipeline** — the production `Validator` stack (`ValidationJob` with
  the default rule registry)

## Baseline and gap register

Recorded in `TODO.conformance.md` (2026-10-20: 20/25 = 80.0% in both
modes). Each failing check maps to a tracked gap; the gap register is the
work queue for the conformance pillar.

## Adding a case

Create the directory, add `schema.xsd`, at least one `valid-*.xml` and one
`invalid-*.xml`, and re-run the rake task. No registration needed — the
runner discovers directories containing `schema.xsd`.
